# Research and Feasibility Findings

Phase 1 of the project: how a macOS app can read and replace selected text in
any application, how it should talk to Claude, and what the platform will not
let us do.

Experiments ran on 2026-09-20 on macOS 26.6.2 (Apple Silicon), Swift 6.3.3,
Command Line Tools only (no Xcode.app), Claude Code 2.1.278. Every finding is
labelled:

- VERIFIED - we ran it on this machine and saw the result.
- SOURCE - read from Apple SDK headers or from the Chromium / WebKit source.
- KNOWN - established platform behaviour we rely on but did not re-test.

## 1. Reading the selected text

Decision: Accessibility API first, clipboard copy as the fallback.

- The Accessibility (AX) API reads the selection with no side effects:
  system-wide element, `kAXFocusedUIElementAttribute`, then
  `kAXSelectedTextAttribute`. Nothing is typed, the clipboard is untouched,
  and it is instant.
- VERIFIED: native AppKit text views report the selection through
  `AXSelectedText`. A secure text field reports subrole `AXSecureTextField`
  and returns no selected text at all, so a password can never be captured
  this way. We additionally refuse any element with that subrole, and refuse
  to run while `IsSecureEventInputEnabled()` is true.
- SOURCE: WebKit (Safari, Mail, Messages, Notes web views) and Chromium
  (Chrome, Arc, Edge, Electron apps) both implement `AXSelectedText`.
- KNOWN: Chromium and Electron only build their accessibility tree when an
  assistive client is detected. When the tree is absent, the AX query returns
  nothing. We deliberately do NOT force it on with `AXEnhancedUserInterface`,
  because that flag has well-documented side effects (it breaks window
  animation in tiling window managers and costs performance in every Chromium
  window). The clipboard fallback covers these apps instead.
- AX calls are synchronous IPC into the target app. A hung app would hang us,
  so every call runs off the main thread with
  `AXUIElementSetMessagingTimeout` set to a short bound.
- Fallback: save the clipboard, synthesize Cmd+C, wait (bounded, up to about
  half a second) for the pasteboard `changeCount` to move, read the text,
  restore the clipboard. An unchanged `changeCount` means nothing was
  selected, which becomes the "Select some text first." message.

## 2. Replacing the selected text

Decision: paste (Cmd+V) is the replacement mechanism everywhere. AX is used to
verify, not to write.

- VERIFIED: writing `AXSelectedText` on an AppKit `NSTextView` or focused
  `NSTextField` replaces the selection, goes through the text delegate,
  registers with the Undo manager (undo restored the original) and is refused
  for non-editable and secure fields.
- SOURCE: Chromium maps the same write to a `kReplaceSelectedText` action and
  WebKit to `setSelectedText`, so the write exists in both engines.
- Why we still do not use the AX write: there is no reliable way to confirm
  from outside that it took effect in a rich web editor (Slack, Notion,
  Google Docs, Gmail). A write that succeeded but looked failed would trigger
  the fallback and insert the correction twice. A duplicated paragraph is
  worse than a briefly borrowed clipboard. Paste goes through every app's
  normal editing path, so it works in rich editors and is undoable with Cmd+Z
  everywhere.
- Safety checks immediately before pasting (the AI call takes about a second;
  the user may have moved on): the same app must still be frontmost, and when
  AX can read the selection it must still equal the captured text. If not,
  nothing is pasted - the correction goes to the clipboard and the user is
  told.
- Terminals (Terminal, iTerm2, Warp, kitty, WezTerm, Alacritty, Ghostty,
  Hyper): a selection there is scrollback, not editable text, and a paste
  would type into the shell prompt. We never paste into them - the correction
  is copied to the clipboard instead.
- Restoring the clipboard too early is the one way this design could destroy
  text (the app would paste the OLD clipboard over the selection). So we
  restore only after a floor delay AND either AX shows the selection changed
  or a cap is reached.

## 3. Clipboard handling

- The whole pasteboard is snapshotted (every item, every type, as raw data)
  and restored afterwards, so copied images, files and rich text survive.
- Temporary content is tagged with the nspasteboard.org marker types
  (`org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType`,
  `org.nspasteboard.ConcealedType`) so clipboard managers skip it.
- If the user copies something themselves while we hold the clipboard
  (`changeCount` moved unexpectedly), we do not restore over it.

## 4. Synthesized keys and keyboard layouts

- VERIFIED: virtual key 8 is "C" only on QWERTY-like layouts. With the Hebrew
  layout active, key 8 types "ב", but with Command held the layout maps it
  back to "c", so Cmd+C keeps working. On Dvorak or AZERTY the key for "c" is
  a different key code entirely.
- So the key codes for "c" and "v" are resolved at run time by translating
  each key code WITH the Command modifier through `UCKeyTranslate` for the
  current layout, falling back to the ASCII-capable layout, then to the ANSI
  defaults.
- Events carry only the Command flag, so a still-held Shift from the
  Cmd+Shift+G press cannot turn the copy into Cmd+Shift+C. On the clipboard
  path we also wait briefly for the user to release the modifiers.
- VERIFIED: `CGPreflightPostEventAccess()` exists in the SDK. Posting events
  is covered by the Accessibility grant; no separate Input Monitoring
  permission is needed because we never listen to the keyboard.

## 5. Global keyboard shortcut

Decision: Carbon `RegisterEventHotKey`. No third-party package.

- VERIFIED: it compiles and registers on macOS 26 from a Command Line Tools
  toolchain, from a process with NO Accessibility and NO Input Monitoring
  permission. It needs no permission and does not observe other keystrokes -
  the system delivers only our combination.
- VERIFIED: registering the same combination twice in one process fails with
  `eventHotKeyExistsErr` (-9878). Registering a combination another process
  already holds SUCCEEDS (it only fails if that process asked for
  exclusivity). Registration failure is therefore not a usable conflict
  detector across apps.
- VERIFIED: `CopySymbolicHotKeys()` returns the system shortcuts (230 entries
  here) with key code, Carbon modifiers and an enabled flag. We use it, plus a
  short built-in list of ubiquitous app shortcuts, to warn about conflicts.
- Rejected: `CGEventTap` (needs Input Monitoring and sees every keystroke -
  against our privacy rules) and `NSEvent.addGlobalMonitorForEvents` (cannot
  consume the key, needs Accessibility).
- Honest trade-off: a global hotkey consumes the combination. The default
  Cmd+Shift+G is "Find Previous" in Safari and many editors and "Go to
  Folder" in Finder and open/save dialogs. While Grammar AI is enabled those
  stop working, so the shortcut is changeable and Settings warns about it.

## 6. Right-click context menu

Decision: a macOS Service. There is no other native option.

- KNOWN: no public API lets an app add items to other apps' context menus.
  Finder Sync is Finder-only; Share and Action extensions live in their own
  menus. Services are the system mechanism, shown under right-click >
  Services (promoted to the top level when few services are enabled) and in
  every app's application menu.
- The service declares both send and return types, so the host app replaces
  the selection itself, natively and undoably, with no clipboard or key
  simulation involved.
- Limits: Services are offered by Cocoa text views (Notes, Mail, TextEdit,
  Safari text fields, Messages, Xcode). Chromium and Electron apps generally
  do not accept returned text, so there the hotkey is the way. macOS may need
  the service enabled once in System Settings > Keyboard > Keyboard
  Shortcuts > Services > Text.

## 7. Permissions, signing and launch at login

- One permission: Accessibility, for reading the selection and posting the
  paste. The app cannot be sandboxed, because the App Sandbox blocks
  controlling other apps through the Accessibility API. This also rules out
  the Mac App Store.
- VERIFIED: an ad-hoc signature's designated requirement is the `cdhash`,
  which changes on every build. macOS ties the Accessibility grant to that
  requirement, so after a rebuild the toggle still shows ON while
  `AXIsProcessTrusted()` returns false. A self-signed code-signing identity
  produces `identifier "..." and certificate leaf = H"..."`, which is
  stable across builds. Hardened runtime works with it and no entitlements
  are needed.
- VERIFIED: a self-signed certificate needs a user trust setting for the Code
  Signing policy before `security find-identity -v` lists it as valid. The
  Apple-shipped LibreSSL writes a PKCS#12 that `security import` accepts;
  OpenSSL 3 needs `-legacy`. `scripts/setup-signing.sh` automates this.
- Permission UX: `AXIsProcessTrusted()` is checked silently. The system
  prompt is requested at most once, from onboarding. The grant is detected
  live by checking once a second only while the permission screen is visible.
- Launch at login uses `SMAppService.mainApp` (macOS 13+). Its status is
  always read live from the system, never cached. VERIFIED: it reports
  `notFound` for a bare executable, so it only works from the real .app
  bundle.
- Public distribution would additionally need a paid Developer ID certificate
  and notarization. The repository builds and runs locally without either.

## 8. Claude integration

Two providers behind one protocol.

Claude Code CLI (`claude -p`) - the default, no API key:

- VERIFIED flags: `-p --output-format json --tools "" --strict-mcp-config
  --disable-slash-commands --no-session-persistence --setting-sources ""
  --system-prompt ...`. No tools, no MCP servers, no skills, no hooks, no
  session saved to disk. The selection goes in on stdin, never in the
  argument list, so it is not visible in `ps`.
- VERIFIED latency, same sentence, wall clock:
  - original setup with `--json-schema` on Haiku: 7 to 9 seconds. The schema
    flag adds a second model turn.
  - single turn, Sonnet, `--effort low`: about 2.5 to 3.3 seconds.
  - the same plus `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`,
    `DISABLE_AUTOUPDATER=1`, `DISABLE_TELEMETRY=1`,
    `DISABLE_ERROR_REPORTING=1`: 1.2 to 1.6 seconds. This is the shipped
    configuration.
  - Haiku through the CLI is slower than Sonnet unless
    `MAX_THINKING_TOKENS=0` is set, because it spends about 300 tokens
    thinking. With it, Haiku also lands near 1.2 seconds.
- Rejected: `--bare` (it never reads the OAuth login, so a Claude
  subscription would not work) and a pre-spawned "warm" CLI process (about
  0.9 seconds per request but roughly 220 MB of idle memory, for a saving of
  a third of a second).
- Because `--json-schema` is too slow, the reply format is enforced by the
  prompt and then parsed and validated by our own `ResponseValidator`, which
  tolerates a markdown fence around the JSON and rejects everything else.

Anthropic API - optional, needs the user's key (stored in the Keychain):

- SOURCE (Anthropic API reference): `POST /v1/messages` with `x-api-key`,
  `anthropic-version: 2023-06-01`, and structured output through
  `output_config.format` of type `json_schema`. The JSON arrives in
  `content[0].text`. A `stop_reason` of `refusal` or `max_tokens` is treated
  as an invalid response and never pasted.
- Not verified live: this machine has no API key. The provider is covered by
  request-shape and response-parsing tests against a fake transport.

## 9. Telling a correction from something else

A model can be talked out of its task by text inside the selection, or can
answer a question instead of fixing it. Length limits do not catch that, so
the validator also scores how much the reply resembles the original, using
Sorensen-Dice similarity over character pairs (case, punctuation and spacing
ignored; character pairs rather than words so that a misspelled original
still matches its fix; identical for every script).

MEASURED scores, same algorithm:

- genuine corrections: "helo wrold" to "Hello world" 0.63; a sentence with
  every word misspelled 0.65; heavy grammar repair 0.72; smoothing in Natural
  mode 0.75; the README example 0.93; tone-preserving and Hebrew fixes 1.00.
- not corrections: an answer to the selected question 0.50 and 0.56; an
  injected unrelated sentence 0.30; a refusal 0.23; a hostile reply to a
  six-letter selection 0.04.
- a legitimate Professional rewrite: 0.39.

Decision: 0.6 and above passes. Below 0.35 (below 0.1 in Professional and
Custom modes, which rewrite on purpose) is rejected and nothing is pasted.
The band in between is not guessed at: the result is flagged and the user
confirms it in the review panel, even if confirmation is switched off. Texts
under 12 letters have too few pairs ("teh" and "the" share none), so they are
compared letter by letter instead and rejected below 0.5.

## 10. Minimum macOS version

macOS 14. It is the oldest release Apple still patches, `SMAppService` needs
13, and Swift Testing (the test framework that works without Xcode) is built
for 14.

## Decisions at a glance

- Capture: AX first, Cmd+C fallback with full clipboard restore.
- Replace: paste only, after re-verifying app and selection; clipboard
  restored once the paste is observed.
- Never paste into terminals or read secure fields.
- Hotkey: Carbon `RegisterEventHotKey`; conflicts via `CopySymbolicHotKeys`.
- Context menu: a Service with return types.
- Claude: CLI by default (about 1.4 s), API key optional; own JSON validation.
- Signing: stable self-signed identity for local builds.
- Tests: Swift Testing through `scripts/test.sh`.

## Known platform limitations

- True injection into other apps' context menus is impossible; Services is
  the native equivalent and is not honoured by Chromium or Electron apps.
- Google Docs renders to a canvas. Copy and paste work there, AX does not.
- Terminals get the correction on the clipboard, not pasted.
- Apps that block synthetic events or keep secure input on cannot be served.
- The default shortcut shadows Find Previous and Go to Folder while enabled.
- The clipboard is borrowed for a moment on the fallback and replace paths.
